ROADMAP DE ESCALAMIENTO - MCHAV ANALYTICS
Célula de Desarrollo 9B - Grupo ASD S.A.S.
=============================================================================

Para escalar el proyecto de un prototipo básico a una plataforma analítica robusta,
se propone el siguiente orden de desarrollo por fases/módulos, resolviendo primero
las dependencias de datos y estructura antes de avanzar a la lógica y la interfaz visual.

-----------------------------------------------------------------------------
FASE 1: AMPLIACIÓN DEL MODELO DE DATOS (ORM)
-----------------------------------------------------------------------------
Objetivo: Sincronizar el archivo backend/models.py con el esquema relacional
completo definido en backend/schema.sql.

Tareas:
[ ] Crear las clases de SQLAlchemy correspondientes a:
    - Rol (tabla: roles)
    - Proyecto (tabla: proyectos)
    - Sprint (tabla: sprints)
    - Issue (tabla: issues)
    - TransicionEstadoIssue (tabla: transiciones_estado_issue)
    - KpisHistoricos (tabla: kpis_historicos)
    - LogsSincronizacion (tabla: logs_sincronizacion)
[ ] Definir correctamente las relaciones (Relationship) y claves foráneas en SQLAlchemy.

-----------------------------------------------------------------------------
FASE 2: MOTOR DE SINCRONIZACIÓN (ETL) E INGESTA
-----------------------------------------------------------------------------
Objetivo: Reemplazar las llamadas directas "al vuelo" a Jira por un proceso de
extracción, transformación y carga (ETL) hacia la base de datos local.

Tareas:
[ ] Crear un servicio o helper para interactuar con la API REST de Jira.
[ ] Desarrollar la lógica de sincronización inicial:
    - Obtener y guardar proyectos asociados al cloudId.
    - Obtener y guardar sprints de cada proyecto.
    - Obtener e insertar todos los issues de cada sprint/proyecto.
    - Obtener el historial de transiciones de cada issue para poblar
      las transiciones de estado.
[ ] Crear un endpoint en FastAPI para disparar esta sincronización de forma manual/asíncrona.
[ ] Implementar el registro de auditoría en la tabla `logs_sincronizacion`.

-----------------------------------------------------------------------------
FASE 3: AUTENTICACIÓN ROBUSTA, SESIONES Y REFRESH TOKEN
-----------------------------------------------------------------------------
Objetivo: Garantizar que la aplicación sea multi-usuario y que los accesos
a Jira no expiren después de una hora.

Tareas:
[ ] Modificar el callback de login en backend/main.py para buscar usuarios por su
    'jira_account_id' en lugar de actualizar el primer registro existente.
[ ] Implementar la rotación del access_token utilizando el 'refresh_token' cuando
    la API de Jira retorne un error 401 (token expirado).
[ ] Asegurar la sesión del usuario usando JWT o cookies firmadas con información del usuario.

-----------------------------------------------------------------------------
FASE 4: MOTOR DE CÁLCULO DE KPIS (LÓGICA DE NEGOCIO)
-----------------------------------------------------------------------------
Objetivo: Calcular métricas ágiles complejas a nivel de base de datos local,
optimizando el rendimiento de las consultas.

Tareas:
[ ] Escribir consultas/funciones para calcular:
    - Lead Time promedio por proyecto/sprint.
    - Cycle Time promedio por proyecto/sprint (calculando la diferencia
      de tiempo en transiciones_estado_issue).
    - Throughput (cantidad de issues finalizados en intervalos de tiempo).
    - Velocity (puntos de historia entregados vs comprometidos).
[ ] Crear tareas automáticas (ej. un cron semanal o diario) para calcular y guardar
    estos valores históricos en `kpis_historicos`.
[ ] Exponer endpoints en la API para consultar estos históricos con filtros por
    proyecto, sprint y rango de fechas.

-----------------------------------------------------------------------------
FASE 5: INTERFAZ VISUAL (FRONTEND DASHBOARD INTERACTIVO)
-----------------------------------------------------------------------------
Objetivo: Mostrar gráficos interactivos en el frontend utilizando la base de datos
local como única fuente de verdad.

Tareas:
[ ] Integrar una biblioteca de gráficos en el frontend (ej. Recharts o Chart.js).
[ ] Diseñar un menú lateral para navegar entre:
    - Dashboard General (Métricas rápidas)
    - Reportes de Proyectos (Gráficos de Velocity, Lead Time, CFD)
    - Configuración (Gestión de usuarios y mapeos)
[ ] Crear controles de filtro (dropdowns para seleccionar Proyecto y Sprint activo).

-----------------------------------------------------------------------------
FASE 6: CONFIGURACIÓN AVANZADA Y WEBHOOKS EN VIVO
-----------------------------------------------------------------------------
Objetivo: Permitir parametrización personalizada de flujos y sincronización en tiempo real.

Tareas:
[ ] Crear una interfaz para mapear los estados personalizados de Jira (ej. "In QA",
    "Ready for Deploy") a estados base del sistema (To Do, In Progress, In Review, Done).
[ ] Implementar Webhooks de Jira en el backend para recibir actualizaciones instantáneas de
    los issues y evitar tener que correr sincronizaciones completas a mano constantemente.
=============================================================================
